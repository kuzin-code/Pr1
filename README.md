# АС «Планирование загрузки и расчёт стоимости» (MVP)

Реализация по `Docs/Техническое_задание_1.0.docx` и `Docs/Бизнес-постановка_v1.7_MVP.docx`.
По файлам STEP и PDF детали система подбирает аналог из журнала калибровки, формирует маршрут,
время этапов с учётом k, себестоимость обработки, срок и загрузку станков с ЧПУ по дням и неделям;
факт пересчитывает k и план.

Стек — см. [docs_dev/STACK.md](docs_dev/STACK.md): Python 3.12, FastAPI + Jinja2, SQLite + SQLAlchemy, pypdf, openpyxl, pytest.

## Запуск

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Linux: .venv/bin/python
.venv/Scripts/python run.py                               # http://127.0.0.1:8000
.venv/Scripts/python run.py --host 0.0.0.0                # доступ из сети участка
.venv/Scripts/python -m pytest                            # тесты
```

Демо-учётные записи (пароль `demo`, сменить перед эксплуатацией): `technolog`, `master`, `operator`,
`head`, `it`, `management` — файл `data/seed/users.json`.
База — `data/app.db`, загруженные файлы — `data/uploads/`. Удалите `data/app.db`, чтобы начать с чистого листа.

## Работа на участке

Учётные записи (пароль `demo` у всех демо-записей — смените в «Мой пароль»; IT управляет записями в «Пользователи»):
`technolog`, `master`, `head`, `it`, `management` — офис; `operator`, `zagotovitel`, `slesar`, `kontroler` — общие
учётные записи специалистов участка (окно «Мои операции»).

Запуск для сети участка и автозапуск при входе в Windows:

```bash
scripts\start_server.bat
```
```bash
powershell -ExecutionPolicy Bypass -File scripts\install_autostart.ps1
```

Обслуживание (резервная копия базы делается сервером раз в сутки в `data/backups`, хранятся 30 последних):

```bash
.venv/Scripts/python manage.py status
```
```bash
.venv/Scripts/python manage.py backup
```
```bash
.venv/Scripts/python manage.py reset-orders --drop-demo-journal
```

`reset-orders` перед запуском в работу удаляет заказы, позиции, операции и факты (сначала делает копию базы);
справочники, станки, пользователи, ставки и журнал калибровки сохраняются.

Рекомендуется установить Python 3.12 с python.org и пересоздать окружение `.venv`.

## Что требует данных заказчика

* **Журнал калибровки**: в `data/seed/journal_demo.json` — 9 условных деталей для демонстрации.
  Реальный журнал загружается через «Журнал калибровки → Импорт из Excel» (формат — «Экспорт в Excel»).
* **Справочник v0.4**: рабочие зоны Mintech V6 и Волжанин-1, точность, мощность и шкала сложности — заглушки,
  сверить и поправить в `data/seed/*.json` до первого запуска (или в БД).
* **Точность чтения 85% (п. 7.2)** проверяется на реальных чертежах участка: STEP — по вершинам и окружностям
  B-rep; PDF — по текстовому слою (сканы без текста → ручной ввод).

## Принятые решения реализации

* Габариты сравниваются в упорядоченном виде (ориентация детали не важна).
* «Подобные» квалитеты — отличие не более чем на 1 квалитет; сложность — равный балл; технология (фрезерная/токарная) должна совпадать.
* Haas ST-20Y принят станком для токарных деталей (технология `turning`).
* Неутверждённые позиции ставятся в очередь после утверждённых, срок — «предварительный».
* Сдвиг срока (ФТ-22) — в рабочих часах 8-часового дня относительно срока на момент утверждения.
* Модель STEP открывается скачиванием во внешний CAD-просмотрщик; PDF — в браузере.
