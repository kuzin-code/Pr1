# Технологический стек (шаг 2)

Основание: `Docs/Техническое_задание_1.0.docx` (ТЗ 1.0), `Docs/Бизнес-постановка_v1.7_MVP.docx` (БП 1.7).
ТЗ технологии не выбирает — выбор сделан исполнителем в рамках Python.

| Слой | Технология | Почему |
|---|---|---|
| Язык | Python 3.12 | Требование «в рамках Python» |
| Доменная логика | чистый Python (`dataclasses`, `enum`) | Формулы ФТ-07…ФТ-21 тестируются без БД и веба |
| Хранение | SQLite + SQLAlchemy 2.0 | Хранение на инфраструктуре предприятия (НФТ-01), без сервера БД, журнал и k сохраняются после перезапуска (НФТ-06) |
| Веб-интерфейс | FastAPI + Jinja2 (HTML-формы, без JS-фреймворков) | ~10 рабочих мест в локальной сети, роли и права (п. 4.5) |
| Сессии | Starlette `SessionMiddleware` (itsdangerous) | «Своя учётная запись на роль», сложный вход не регламентируется |
| Чтение STEP | собственный парсер ISO 10303-21 (текстовый) | Габариты, число тел, единицы; без внешних сервисов |
| Чтение PDF | `pypdf` + регулярные выражения | Материал, квалитеты/допуски, резьбы (ФТ-04) |
| Импорт журнала | `openpyxl` | Журнал калибровки ведётся в Excel (ФТ-25) |
| Тесты | `pytest`, `httpx` (FastAPI TestClient) | Разработка через тестирование |
| Сервер | `uvicorn` | Запуск в локальной сети |

Внешних сетевых соединений приложение не устанавливает (НФТ-01).

## Ограничения кода
* модульная структура, не более 500 строк в файле (проверяется тестом `tests/test_code_limits.py`);
* домен не зависит от БД и веба; сервисы связывают домен и хранилище; веб — тонкий слой.
